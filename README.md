# Service Portal — портал обслуживания коммерческих помещений

Веб-приложение для сервисной компании, которая обслуживает офисы, магазины и другие коммерческие объекты.
Клиент сообщает о проблеме и следит за ходом работ. Мастер видит ближайший выезд, выполняет работу и прикладывает отчёт.
Диспетчер, склад и финансы выполняют «скрытую» работу так, чтобы клиенту и мастеру не нужно было разбираться в договорах, статусах и проводках.

> **Статус:** пилотная разработка. Реальные платежи отключены (`config/portal.php → live_payments = false`), YooKassa работает только в песочнице.

## Возможности

**Клиент**
- Заявка одной короткой формой: объект, «Что случилось?», по желанию место и до 5 фото. Повторное нажатие не создаёт вторую заявку.
- Карточка заявки с одним следующим шагом, временем выезда по часовому поясу объекта и перепиской.
- Кнопка «Время не подходит»: это запрос диспетчеру, само назначение не меняется.
- Ответственный представитель клиента рассматривает диагностику и смету (в том числе одним явным составным подтверждением), оплачивает аванс и остаток, принимает результат или отправляет замечание.
- По завершённой заявке — «Сообщить о новой проблеме»: создаётся новая заявка, связанная со старой.

**Мастер**
- «Сегодня и дальше»: ближайший выезд первым, адрес, доступ, контакт с кнопкой звонка.
- Начало работы проверяется на сервере: назначение, другие активные выезды, готовность материалов, утверждённая смета и аванс.
- Чек-лист, фото, отчёт и фактический расход материалов с автосохранением черновика и видимыми состояниями «Сохраняем… / Не сохранено / Сохранено».
- «Нужна помощь» и «Не могу продолжить»: выезд прерывается, сделанная работа сохраняется, диспетчер получает уведомление.
- Ведущий мастер получает собранный итог команды и передаёт результат клиенту. Если мастер на объекте один, это делается одним действием.

**Персонал**
- Диспетчер: виды работ, договор, ведущий мастер, планирование и перенос выездов, продолжение прерванной работы, разбор замечаний.
- Склад: каталог, закупки, резерв, выдача и возврат материалов без ухода в минус.
- Финансы: сметы и их ревизии, авансы 50 %, банковские поступления, распределение платежей, итоговые счета, возвраты, фискализация (после утверждения бухгалтером).
- Администрирование: приглашения, роли, доступ к объектам, двухфакторная аутентификация (TOTP) и её сброс.

**Надёжность**
- Каждое изменяющее действие идемпотентно: у него есть ключ операции, и повтор возвращает уже сохранённый результат.
- Оптимистичные версии записей: если данные изменились, решение не применяется наполовину.
- Журнал аудита и outbox для уведомлений в портале и по почте.
- Возврат из браузера после оплаты никогда не отмечает счёт оплаченным. Статус подтверждает только сервер по данным YooKassa.

## Роли

| Роль | Что видит | Чего не видит |
|---|---|---|
| Контакт клиента | Заявки своих объектов, переписку, время выездов | Суммы, сметы, кнопки приёмки |
| Представитель клиента (`accept_work`) | Всё по своей организации, решения и оплату | Внутренние записи, складские и финансовые инструменты |
| Мастер (`technician`) | Свои выезды, историю, задачи ведущего | Списки заявок организации, финансы, закупки |
| Диспетчер (`dispatcher`) | Все заявки и планирование | — |
| Склад (`warehouse`), финансы (`finance`), администратор (`administrator`) | Отдельные рабочие места | — |

## Технологии

- PHP 8.4, [Laravel 13](https://laravel.com), [Livewire 4](https://livewire.laravel.com)
- SQLite по умолчанию (подходит любая СУБД, которую поддерживает Laravel)
- Vite + Tailwind CSS 4, шрифты Golos Text / Oswald
- Pest / PHPUnit, `node --test` для клиентской логики черновиков
- `pragmarx/google2fa` и `bacon/bacon-qr-code` для двухфакторной аутентификации
- Laravel Pint для форматирования

## Быстрый старт

Нужны PHP 8.4 с расширениями `bcmath`, `pdo_sqlite`, `gd` (с поддержкой JPEG, PNG и WebP), `exif` и `fileinfo`, Composer 2, Node.js 20+.

```bash
git clone <url-репозитория> service-portal
cd service-portal/application

composer install
cp .env.example .env
php artisan key:generate
touch database/database.sqlite      # на Windows: type nul > database\database.sqlite
php artisan migrate

npm install
npm run build

php artisan serve                   # http://localhost:8000
```

Для разработки с горячей перезагрузкой: `composer run dev`.

## Демо-данные

Демо-данные загружаются только в окружении `local` при `PORTAL_DEMO=true`:

```bash
# в .env: APP_ENV=local, PORTAL_DEMO=true
php artisan db:seed
php artisan portal:password client@example.test   # пароль запрашивается интерактивно, минимум 12 символов
```

Учётные записи (`@example.test`): `client` (представитель клиента), `contact` (контакт объекта), `other` (другая организация), `dispatcher` (диспетчер и администратор), `technician` (ведущий мастер), `worker`, `electrician`.
Все пароли случайные. Задайте их командой `portal:password`.

## Фоновые задачи

Уведомления, почта и сверка платежей идут через планировщик. На сервере добавьте в cron:

```cron
* * * * * cd /path/to/application && php artisan schedule:run >> /dev/null 2>&1
```

| Команда | Назначение |
|---|---|
| `portal:deliver-notifications` | Доставка событий outbox в уведомления портала |
| `portal:deliver-email` | Отправка писем с повторной проверкой получателя и прав |
| `portal:reconcile-payments` | Команды к YooKassa (песочница) и сверка с авторитетным статусом провайдера |

## Конфигурация

Основные переменные `.env` (полный список — в `.env.example` и `config/portal.php`):

| Переменная | Назначение |
|---|---|
| `PORTAL_COMPANY` | Название компании в интерфейсе и письмах |
| `PORTAL_SUPPORT_EMAIL`, `PORTAL_SUPPORT_PHONE` | Контакты на странице «Помощь» |
| `PORTAL_DEMO` | Разрешает демо-данные и `portal:password` (только `local`) |
| `PORTAL_EMAIL_ENABLED` | Включает отправку писем (нужен настроенный `MAIL_*`) |
| `PORTAL_FINANCE_APPROVED`, `PORTAL_LEGAL_HEADER`, `PORTAL_TAX_LABEL` | Разрешение выпуска финансовых документов и их реквизиты |
| `YOOKASSA_SANDBOX_ENABLED`, `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY` | Песочница YooKassa |
| `APP_LOCALE` | Язык интерфейса и дат, по умолчанию `ru` |

Схема фискализации (`portal.finance.fiscal`) по умолчанию не утверждена. Пока бухгалтер явно не заполнит и не утвердит параметры, чеки не формируются.

## Принципы проектирования

Основаны на [пользовательских сценариях](service-portal-user-scenarios.md):

1. Страница-задача отвечает на три вопроса: что происходит, что мне сделать, что будет дальше.
2. На каждом шаге одно основное действие.
3. Состояние ожидания называет того, за кем следующий шаг, и не выглядит как ошибка пользователя.
4. Успех показывается только после подтверждения сервером. Несохранённый ввод остаётся на странице.
5. Согласие, оплата и приёмка — только явные решения. Удобство никогда не подразумевает скрытого согласия.
6. Мобильный формат по умолчанию: всё работает на ширине 360 px, области нажатия не меньше 44×44 px.
7. Только онлайн. Переходы статусов и финансовые действия не ставятся в очередь офлайн.
